# Skills

## `aseprite-pixel-art`

A production skill for game-ready pixel art through the Aseprite MCP server. It covers static
assets, frame animation, tilesets, UI icons, effects, audits, and the exact MCP op workflow
(`apply_operations` / `inspect` / `run_lua`).

### Requirements

- The Aseprite MCP server from this repository, configured in your client. See the root
  [README](../README.md) for the 30-second config and `ASEPRITE_PATH`.
- Aseprite 1.3+ installed (or `ASEPRITE_PATH` pointing at the executable).
- The repo's Python environment (`fastmcp`, `pillow`) for the example builders and
  `scripts/pixelqa.py`.
- A client that supports Agent Skills (`SKILL.md` + optional `references/`, `scripts/`,
  `assets/`). Qoder discovers user skills in `~/.qoder/skills/<name>/`.

### Install

Copy the whole folder — `SKILL.md`, `references/`, `scripts/`, `assets/`, and `examples/` — not
just `SKILL.md`.

```bash
# Qoder / Claude Code style user-level skills (Windows Git Bash)
mkdir -p ~/.qoder/skills
cp -r skills/aseprite-pixel-art ~/.qoder/skills/

# project-level alternative (if your client supports project skills)
mkdir -p .qoder/skills
cp -r skills/aseprite-pixel-art .qoder/skills/
```

If your client reads project skills from another directory (`.claude/skills`, `.cursor/skills`,
etc.), copy the same folder there. The skill is self-contained; relative links inside it assume
the folder layout is preserved.

To avoid a duplicated copy during development, a directory junction/symlink also works:

```powershell
# Windows, run in PowerShell as the user
New-Item -ItemType Junction -Path "$env:USERPROFILE\.qoder\skills\aseprite-pixel-art" `
  -Target "D:\Projects\Aseprite_MCP\skills\aseprite-pixel-art"
```

Do not copy only `SKILL.md`: references and scripts are loaded on demand by relative path.

### Invoke

Mention the skill by name or ask for the task in its trigger domain:

```text
Use aseprite-pixel-art to draw a 16x16 health potion icon with a transparent background,
a 1px outline, and a readable red liquid. Inspect it at 1x, then export PNG and .ase.

Use aseprite-pixel-art to make a 32x32, 8-frame hopping moss slime with a leaf sprout.
Use per-frame durations, tag the loop "hop", and verify frame consistency and loop closure.
```

The skill itself does not expose new tools; it instructs the agent to use the existing
`apply_operations`, `inspect`, and `run_lua` tools. If the MCP is not connected, the agent
should stop and ask for the config instead of pretending to draw.

### Verify the skill

Run the included examples; they exercise the real MCP, not a mock:

```bash
# from the repository root
export ASEPRITE_PATH=/path/to/aseprite
python skills/aseprite-pixel-art/examples/potion-icon/build.py
python skills/aseprite-pixel-art/examples/slime-hop/build.py
```

Both builders print a JSON summary and exit non-zero on any failed gate. To run the QA
independently:

```bash
python skills/aseprite-pixel-art/scripts/pixelqa.py --help
```

### Notes

- The example `.ase` files are generated by the builders. The repository `.gitignore` ignores
  `*.ase`; force-add them or regenerate them if you publish the examples.
- `pixelqa.py` is a QA helper, not part of the MCP. It checks the files that actually ship;
  `inspect` remains the in-Aseprite perception tool.
- RGB is the default and safest mode. Indexed mode now works with the draw ops: call
  `set_palette` before painting and remember that palette index 0 is Aseprite's transparent
  index. Verify `metrics.palette`; the mapping uses RGB distance, so near-duplicate palette
  entries are ambiguous.
